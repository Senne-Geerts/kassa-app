# Kassa App

A modern Point of Sale (POS) system designed for event-based food and beverage sales, built for organizations like youth movements (Chiro) running temporary events.

## Architecture

This is a monorepo containing:

- **Backend**: Spring Boot 4.1 REST API (Java 21)
- **Frontend**: Next.js 16.4.3 with React 19.3.0

### Data Model

```
Event (menu edition)
  ├─ Category (menu section, e.g., "Drinks", "Snacks")
  │   └─ Product (menu item with price)
  └─ Order (sale/checkout)
      └─ OrderLine (product + quantity)
```

### How It Works

1. **Setup**: Create an event with categories and products (menu items)
2. **Service**: Volunteers take orders on paper menus during the event
3. **Checkout**: When a party leaves, another volunteer uses the app to enter the paper menu items and calculate the total
4. **Summary**: View sales statistics and revenue per event

## Getting Started

### Prerequisites

- **Java 21** (for backend)
- **Node.js 18+** (for frontend)
- **PostgreSQL** (or use Nix for automatic setup)
- **Maven** (or use included wrapper `./mvnw`)
- **Nix** (optional, for dev environment)

### Backend Setup (api/)

1. **Start the database**:
   ```bash
   # With Nix (recommended)
   cd api
   nix develop -c pg:setup
   nix develop -c pg:start
   
   # Or configure your own PostgreSQL on port 5433
   ```

2. **Run the API**:
   ```bash
   cd api
   ./mvnw spring-boot:run
   ```

3. **Run tests**:
   ```bash
   ./mvnw test
   ```

The API will be available at `http://localhost:8080`

### Frontend Setup (frontend/)

1. **Install dependencies**:
   ```bash
   cd frontend
   npm install
   ```

2. **Run the development server**:
   ```bash
   npm run dev
   ```

The frontend will be available at `http://localhost:3000`

## API Endpoints

### Events
- `GET /api/events` - List all events
- `POST /api/events` - Create new event
- `GET /api/events/{id}` - Get event details
- `PUT /api/events/{id}` - Update event
- `DELETE /api/events/{id}` - Delete event
- `GET /api/events/{id}/summary` - Get sales statistics

### Categories & Products
- `GET /api/events/{id}/categories` - List categories for an event
- `POST /api/events/{id}/categories` - Create category
- `PUT /api/events/{id}/categories/{categoryId}` - Update category
- `DELETE /api/events/{id}/categories/{categoryId}` - Delete category
- `POST /api/events/{id}/categories/{categoryId}/products` - Add product to category

### Orders
- `GET /api/events/{id}/orders` - List orders for an event
- `POST /api/events/{id}/orders` - Create new order (checkout)

- **Dev Environment**: Nix (flake-based)
- **Database Port**: 5433 (to avoid conflicts)

## Development Patterns

- **DTOs**: Request/response objects separate API contracts from domain models
- **Service Layer**: Business logic lives in services, controllers handle HTTP concerns
- **Client-Generated IDs**: Order IDs are UUIDs generated by the client to prevent duplicate sales on retry
- **Event Cloning**: Copy menu structure (categories + products) without orders for recurring events

## Use Case Example

**Chiro Event Workflow**:
1. Event organizer creates "Summer BBQ 2026" event in the app
2. Adds categories: "Drinks", "Food", "Snacks"
3. Adds products with prices to each category
4. During event: Volunteers write orders on paper menus
